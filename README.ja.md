# SNS Media Downloader

🌐 [English](README.md) | 日本語

> **画面に映っているメディアの、すぐ隣に保存ボタンを置きます。**

**SNS Media Downloader** は、**X（Twitter）** と **Bluesky** 向けのブラウザ拡張機能です。

メディアのある投稿の操作バーにダウンロードボタンを追加し、**オリジナルのファイル**
（原寸の画像、最高ビットレートの動画）を、自分で決めたファイル名でダウンロードフォルダへ直接保存します。

API キーも、外部サービスも、ZIP の解凍も、「この投稿を当サイトで開いてください」も必要ありません。

---

## 🤔 何が便利なの？

画像 1 枚なら右クリックで保存できます。面倒になるのはそこから先です。

| やりたいこと | ブラウザ標準でできること | この拡張機能がすること |
| :--- | :--- | :--- |
| 原寸の画像がほしい | 画面に表示されていたサイズの画像が保存される | `name=orig` を付けて原寸で取得し直す |
| 動画を保存したい | 何もできない。X の動画は `blob:` URL で、ページ内でしか通用しない | 本物の MP4 URL を拾い、最高ビットレートを選ぶ |
| 4 枚まとめて保存したい | 右クリック 4 回、ダイアログ 4 回 | クリック 1 回 |
| 後から探せるファイル名で | `GxAbCdEfGhIjKlM.jpg` | `x/example_user-1234567890123456789-20260819_142530-img2.jpg`（自由に変更可） |

## ✨ 主な機能

* 🐦 **2 サイト対応** — X（Twitter）と Bluesky。それぞれ専用のアダプタとアクセント色を持ちます。
* 🖼️ **プレビューではなく原本** — X の画像は `name=orig`、動画は最高ビットレートの MP4、
  Bluesky は投稿者本人の PDS から `com.atproto.sync.getBlob` で実体を取得します。
* 🎯 **投稿全体でも 1 件だけでも** — 操作バーのボタンは全件保存。サムネイル右上の小さなボタンは
  その 1 件だけ（メディアが 2 件以上のときに出ます）。
* ❤️ **いいねと同時に保存** — いいねを押すだけで、その投稿のメディアを保存できます。
  **既定はオフ**。必要な人だけ設定画面で有効にしてください。
* 📊 **進み具合と保存済みが一目で分かる** — 画面左下に「DL待ち」「DL完了」（失敗があれば「DL失敗」）の
  件数を表示します。保存したメディアのボタンは緑のチェックマークに変わり、ページを移動しても
  再読み込みしても、ブラウザを閉じるまでその表示が続きます。
* 🏷️ **ファイル名テンプレート** — 24 種類の変数、サブフォルダ、条件ブロック、文字数制限。
  入力中に 4 パターンのサンプルでライブプレビューされます。
* 🔁 **失敗したら自動で再試行** — 最大 3 回まで、間隔を少しずつ空けながらやり直します。
  それでも駄目な場合はエラーとして通知し、書きかけのファイルは残しません。
* 🔑 **API キー不要・アカウント登録不要** — 何も申請せず、何にもログインしません。
* 🌍 **9 言語の UI** — 日本語・English・한국어・Deutsch・Español・Français・Português (BR)・简体中文・繁體中文。
* 🌗 **OS のライト／ダークテーマに追従**。「視差効果を減らす」設定も尊重します。
* 🔒 **解析なし・テレメトリなし・開発者のサーバーなし** — 詳しくは [PRIVACY.md](PRIVACY.md) へ。

## 🛠️ インストール方法

ビルド工程はありません。リポジトリがそのまま拡張機能です。

### 🌐 Chrome / Edge / Brave など Chromium 系ブラウザ

1. このリポジトリを ZIP でダウンロードして解凍します（`git clone` でも構いません）。
2. アドレスバーに `chrome://extensions` と入力して開きます。
3. 画面右上の **「デベロッパー モード」** をオンにします。
4. **「パッケージ化されていない拡張機能を読み込む」** をクリックし、解凍したフォルダ
   （`manifest.json` が入っている階層）を選びます。

> 一度読み込めば、削除するまで有効なままです。パズルピースのアイコンからツールバーに固定できます。

### 🦊 Firefox

> **先にマニフェストを差し替えてください。** `manifest-firefox.json` を `manifest.json` へ
> 上書きコピーします。Chrome 版のマニフェストはバックグラウンドをサービスワーカーとして
> 宣言しており、Firefox はこれに対応していません。そのまま読み込むとインストール自体は
> 通りますが、バックグラウンドが起動しないため、ダウンロードも API 取得も一切動きません。

**A. 一時的な読み込み（手軽ですが、Firefox を閉じると消えます）**

1. アドレスバーに `about:debugging#/runtime/this-firefox` と入力して開きます。
2. **「一時的なアドオンを読み込む…」** をクリックします。
3. 解凍したフォルダ内の **`manifest.json`** を選択します。

**B. 恒久的なインストール（Developer Edition / Nightly 限定）**

1. フォルダの**中身**を ZIP 圧縮します（フォルダごとではありません）。
2. `about:config` を開き、`xpinstall.signatures.required` を **`false`** に変更します。
3. `about:addons` を開き、右上の ⚙️ から **「ファイルからアドオンをインストール…」** で ZIP を選びます。

### ✅ 動作確認

[x.com](https://x.com/) か [bsky.app](https://bsky.app/) で画像付きの投稿を開いてください。
返信・リポスト・いいねが並ぶ行に ⬇️ ボタンが増えていれば成功です。押すと画面左下に
件数が表示され、保存が終わるとボタンが緑のチェックマークに変わります。

## 🕹️ 使い方

| ボタン | 場所 | 保存されるもの |
| :--- | :--- | :--- |
| **メインボタン** | 操作バーの中（いいね・ブックマークの並び）。メディアが 2 件以上あると枚数バッジが付きます。 | その投稿のメディア全件 |
| **個別ボタン** | 各サムネイルの右上。メディアが **2 件以上** のときだけ表示されます。 | そのメディア 1 件だけ |
| **いいねボタン** | サイト本来のいいねボタン。設定でオンにしたときだけ働きます。 | その投稿のメディア全件 |

### ダウンロード数カウンター

保存の進み具合は、画面左下のカウンターに表示されます。

| ラベル | 数えているもの |
| :--- | :--- |
| **DL待ち** | 順番を待っているファイルと、転送中のファイル |
| **DL完了** | 保存できたファイル |
| **DL失敗** | 再試行しても保存できなかったファイル（1 件以上あるときだけ表示） |

数はファイル単位で、開いているすべてのタブの合計です。ボタンからの保存も、いいねによる保存も
同じように数えます。DL待ちが 0 になってから **5 秒後**にカウンターは消え、そのとき完了数と
失敗数も 0 に戻ります。5 秒のうちに次の保存が始まった場合は、数を引き継いだまま表示を続けます。

カウンターはクリックを素通りさせるため、その下にあるサイト側のボタン（アカウント切り替えなど）も
普段どおり押せます。画面の狭いスマホ表示では、下部のナビゲーションバーの上に表示されます。

失敗があったときは、トーストでも知らせます。一部だけ失敗した場合は「$1件保存 / $2件失敗」、
1 件も保存できなかった場合は「$1件のダウンロードに失敗しました」の形になります。
すべて成功したときはトーストを出しません（件数はカウンターで分かるためです）。
なお失敗した項目は最大 3 回まで自動で再試行され、それでも完了しなかったものは
履歴ごと取り除かれるため、中途半端なファイルは残りません。

### 保存済みの表示

保存が完了したメディアは、ボタンの見た目が変わります。

* **個別ボタン** — 緑のチェックマークになり、マウスを乗せなくても常に表示されます。
  4 枚組のどれを保存したか、一目で分かります。
* **メインボタン** — 投稿のメディアをすべて保存するとチェックマークになります。
  一部だけ保存した場合は、枚数バッジが「2/4」のような形になります。

済みのボタンも、押せば何度でも保存し直せます。この記録は「投稿 ID ＋ 何枚目か」で持つため、
同じ投稿がリポストや別のタブに出てきても同じ表示になり、ページを移動しても再読み込みしても残ります。

記録は**ブラウザを閉じると消えます**。拡張機能を更新・再読み込みしたときも消えます。
シークレットウィンドウで保存した分は通常ウィンドウとは別に記録され、
シークレットウィンドウをすべて閉じた時点で消えます。

### いいねと同時に保存する

設定画面の **「いいねしたときも同時にダウンロードする」** をオンにすると、いいねボタンが
保存も兼ねるようになります。ファイル名・保存先・同名時の動作は、ダウンロードボタンを
押した場合とまったく同じです。変わるのは**保存が始まるきっかけ**だけで、
できあがるファイルは変わりません。

**既定はオフ**にしてあります。押した覚えのないダウンロードが始まるほうが、
クリックが 1 回必要なことより驚きが大きいためです。知っておくとよい点が 4 つあります。

* **いいねを付けたときだけ動きます。** 外したときは何も起きません。この 2 つは内部的には
  別のボタンで、「まだ押していない」ほうだけを見ているためです。
* **文字だけの投稿は静かに見送ります。** トーストもエラーも出ず、本当に何も起きません。
* **保存済みのメディアは、いいねでは保存し直しません。** いいね → 取り消し → もう一度いいね、と
  操作してもファイルは 1 組だけです。ボタンで保存済みの投稿にいいねした場合も同じで、
  全件保存済みなら何も起きず、一部だけ保存済みなら残りの分だけを保存します。
  判断には前述の「保存済みの表示」と同じ記録を使うため、ブラウザを閉じるまで有効です。
  （ボタンからなら、保存済みでも何度でも保存できます。）
* **いいねそのものには手を触れません。** クリックを見ているだけで、サイト側の処理を
  取り消したり遅らせたりはしません。

### あえて対象外にしているもの

* **引用投稿。** 引用先のメディアは引用先の投稿のものなので、両サイトとも除外しています。
  引用元の投稿を開けば、そちらに専用のボタンが出ます。
* **リンクカードのプレビュー画像**（X の `card.*`、Bluesky の `<a href="http…">` 内の画像）。
* **Tenor などの外部 GIF 埋め込み。** サイト自身がホストしているファイルではないためです。
* **ライトボックス（画像の拡大表示）。** 拡大表示にはボタンを出しません。投稿側のボタンを使ってください。
* アイコン画像・ヘッダー画像など、投稿メディア以外のもの。

## 🏷️ ファイル名

既定のテンプレートはこれです。

```
{site}/{user}-{id}-{datetime}-{kind}{n}.{ext}
```

4 枚組の X 投稿の 2 枚目なら、こうなります。

```
x/example_user-1234567890123456789-20260819_142530-img2.jpg
```

設定画面では、入力するそばから 4 パターンのサンプルが更新されます。
実際に保存してみないと結果が分からない、ということはありません。

### 変数一覧

**投稿者・投稿**

| 変数 | 中身 |
| :--- | :--- |
| `{site}` | `x` または `bsky` |
| `{user}` | ユーザー ID（X）またはハンドル（Bluesky） |
| `{name}` | 表示名 |
| `{id}` | 投稿 ID |
| `{text}` | 本文（URL は除去されます） |

**日時** — 投稿日時を、閲覧している端末のローカルタイムに変換した値です

| 変数 | 例 |
| :--- | :--- |
| `{datetime}` | `20260819_142530` |
| `{date}` | `20260819` |
| `{time}` | `142530` |
| `{yyyy}` `{mm}` `{dd}` | `2026` `08` `19` |
| `{hh}` `{mi}` `{ss}` | `14` `25` `30` |
| `{dl_date}` `{dl_datetime}` | 投稿日時ではなく、**ボタンを押した日時** |

**メディア**

| 変数 | 中身 |
| :--- | :--- |
| `{n}` | 投稿内の通し番号 `1`, `2`, `3` … |
| `{nn}` | 同上のゼロ埋め `01`, `02` … |
| `{n?}` | `{n}` と同じ。ただしメディアが 1 件のときは空 |
| `{total}` | その投稿のメディア総数 |
| `{kind}` | `img` / `vid` / `gif` |
| `{ext}` | `jpg`, `png`, `mp4`, `webm` など |
| `{media_id}` | 元ファイルの ID。Bluesky なら CID、X なら画像・動画のハッシュ |
| `{res}` | X の動画なら `1280x720`、Bluesky ならアスペクト比、X の画像なら `orig` |

### 記法

| 記法 | 意味 |
| :--- | :--- |
| `/` | サブフォルダの区切り（ダウンロードフォルダからの相対パス） |
| `[ … ]` | 条件ブロック。中の変数が 1 つでも空なら、**ブロックごと消えます** |
| `\[` `\]` | 角かっこを文字としてそのまま出力 |
| `:20` | 文字数制限。`{text:20}` や `{name:12}` のように、どの変数にも付けられます |

条件ブロックがあるおかげで、1 つのテンプレートを全パターンで使い回せます。
`{user}-{id}[-{res}].{ext}` は、X の動画なら `user-123-1280x720.mp4`、画像なら `user-123.jpg` になり、
ハイフンだけが取り残されることがありません。

### 変換時に自動で行われること

* ファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）は**変数の値から**取り除かれます。
  そのため、表示名にスラッシュが入っていても勝手にフォルダが掘られることはありません。
* テンプレートに直接書いた `:` や `?` などの使えない文字も、保存前に取り除かれます。
* 連続する空白・改行は半角スペース 1 個にまとめ、前後の空白は削除します。
* 文字数制限（`:20` など）は**見た目の 1 文字単位**で数えるため、`👨‍👩‍👧` のような結合絵文字も
  途中で割れません。
* 各階層の前後にあるドットと空白を除去し、空になった階層は捨てます。
  この処理により `..` がパスに残ることもありません。
* 各階層（フォルダ名・ファイル名）は UTF-8 で **150 バイト**までに切り詰めます。
  日本語ならおよそ 50 文字、英数字ならおよそ 150 文字です。ファイル名は拡張子を残して本体側を削ります。
  多くの OS はファイル名の上限が 255 バイトで、ブラウザが保存中に付ける一時的な接尾辞などの分を残しています。
* `CON`・`NUL`・`COM1` のような Windows の予約名になった階層は、先頭に `_` を付けます。
* ファイル名部分が空になった場合は `download` という名前で保存されます。
* テンプレート自体が空欄（空白だけ）の場合は、既定のテンプレートを使います。
* `{toString}` のような、変数一覧に無い名前は空文字として扱います（入力欄の下に警告が出ます）。

## ⚙️ 設定項目

ツールバーのアイコンをクリックすると設定画面が開きます（拡張機能の「オプション」から開いても同じ画面です）。

| 設定項目 | 既定値 | 説明 |
| :--- | :--- | :--- |
| **ファイル名** | `{site}/{user}-{id}-{datetime}-{kind}{n}.{ext}` | テンプレート本体。`[ ]` の対応、未知の変数、`{ext}` の欠落は入力欄の下に警告が出ます。 |
| **同名時** | 連番を付けて保存 | `uniquify` / `overwrite` / `prompt`。ブラウザのダウンロード API にそのまま渡されます。Firefox は `prompt`（毎回確認する）に対応していないため、Firefox では選択肢に出ません。 |
| **常に保存ダイアログを表示する** | OFF | 1 ファイルごとに保存先を尋ねます。 |
| **いいねしたときも同時にダウンロードする** | OFF | いいねを押すと、その投稿のメディアも保存します（前述）。 |
| **既定値に戻す** | — | 上記 4 つをまとめて初期状態へ。 |

「保存」ボタンはありません。スイッチと選択肢は切り替えた瞬間に、ファイル名は入力が止まってから
約 0.4 秒後（または入力欄を離れたとき・画面を閉じたとき）に自動保存され、隅に「保存しました」が
短く表示されます。

設定は `storage.sync` に保存されるため、同じブラウザアカウントでログインしていれば他の端末にも
引き継がれます。保存済みの表示に使う記録（投稿 ID と、その投稿の何枚目を保存したか）は
設定とは別の `storage.session` に置かれ、同期されず、ブラウザを閉じると消えます。

## 💡 動作の仕組み

両サイトとも共通処理（`shared/core.js`）を通ります。投稿を見つける、ボタンを差し込む、
ファイル名を組み立てる、`{url, filename}` の配列をバックグラウンドへ渡す、カウンターと
ボタンの見た目を更新する、失敗したらトーストを出す。
サイト固有の部分だけがアダプタに入ります。そしてこの 2 つのアダプタは、まったく違う問題を解いています。

### X — ページが既に受け取った応答を読む

動画プレイヤーの `<video>` には `src="blob:https://x.com/…"` が入っています。
blob URL は「ページが既にメモリ上に持っているデータ」への参照にすぎず、ページの外では何の意味も持たず、
ダウンロードにも使えません。本物の MP4 URL は、その少し前に X 自身が取得した GraphQL の JSON の中にあります。

そこで `sites/x/interceptor.js` は **MAIN world**（ページと同じ JavaScript の世界。
`window.fetch` を差し替えられる唯一の場所）で動き、`fetch` と `XMLHttpRequest` をモンキーパッチします。
`/graphql/` または `/i/api/` 宛ての通信について、レスポンスを `clone()` してから
（本体は 1 回しか読めないので、X 自身の取り分を残す必要があります）JSON を再帰的に走査し、
`extended_entities.media` を伴う `rest_id` / `id_str` をすべて拾います。

X は API の応答を大量に受け取るので、この処理はすべて X の画面表示の上乗せになります。
そこで、応答はまず文字列のまま受け取り、`"media_url_https"` を含まないもの（通知の件数や設定など、
メディアの無い応答）は JSON として解析せずに見送ります。解析と走査は、`requestIdleCallback` で
ブラウザの手が空いたときに回します（遅くとも 1 秒以内には終わるので、保存ボタンを押すまでには間に合います）。
例外は XHR の `responseType` が `"json"` の場合で、ブラウザが解析済みのオブジェクトを X が後から
書き換えることもあるため、その場で調べます（解析し直す必要が無いので軽く済みます）。

画像は `pbs.twimg.com/media/…?format=…&name=orig` の形へ。動画は `variants` を `video/mp4` に絞り、
ビットレート降順に並べて先頭を採用します。結果は `postMessage` で content script へ渡され、
受信側で中身を検証してからキャッシュされます。ページ側のスクリプトも同じ形のメッセージを送れてしまうため、
URL は `pbs.twimg.com` / `video.twimg.com` の https、拡張子は画像と mp4 のものだけを受け入れます。
変換できなかったメディアは `null` のまま残し、画面上の並びと番号がずれないようにしています。
キャッシュの鍵は投稿 ID と動画 ID の 2 通りです。後者はサムネイルの `poster` 属性から復元できるため、
投稿 ID が辿れない状況でも動画を特定できます。

横取りに間に合わなかった場合（パーマリンクで直接開いた、スクリプトより先に配信された、など）は
`scrapeDom()` が引き継ぎ、DOM から拾えるものを組み立てます。`name=orig` の画像、
サムネイル名から実体 URL を復元できる GIF、そして `src` が blob ではない動画です。

### Bluesky — URL の中に必要な情報がすべて入っている

こちらは横取りが不要です。画像 URL は
`cdn.bsky.app/img/feed_…/plain/{did}/{cid}@jpeg`、動画のポスターは
`video.bsky.app/watch/{did}/{cid}/…` という形をしています。
DID がアカウントを恒久的に指し、CID がファイルを内容によって指す。
`com.atproto.sync.getBlob` に必要なのはこの 2 つだけです。

一方 DOM からは、本文・投稿日時・正確な MIME タイプ・解像度が取れません。
そこで保存ボタンを押した時点で `app.bsky.feed.getPosts` を **1 回だけ**呼び、それらを補います。
投稿日時に使うのは `indexedAt`、つまりサーバーが投稿を受け取った時刻です。
`record.createdAt` は投稿者の端末が自己申告した値なので、使いません。
実体は投稿者本人の PDS から取得し、PDS は `plc.directory`（または `did:web` の DID ドキュメント）で
解決して、失敗時は `bsky.social` にフォールバックします。

これらの通信はすべて「あれば嬉しい」もので、必須ではありません。API に届かなくても、
DOM 由来の DID と CID だけでダウンロード URL は成立します。失われるのはメタ情報の精度だけです。

### ボタンの差し込み

両サイトともスクロールに応じてタイムラインを作り替え続けるため、待ち受けられる読み込み完了イベントが
存在しません。そこで `MutationObserver` で文書全体を監視しますが、X も Bluesky も DOM が絶えず変わるので、
画面全体を走査し直すことはせず、次のように**変化した投稿だけ**を見直します。

* **見直す投稿を絞る。** 投稿を含む要素が追加されたとき、投稿の中で「ボタンに関係する要素」
  （アダプタの `watch`。メディア・投稿へのリンク・操作バーのボタン）が増減したとき、
  画像の `src`・動画の `poster`・リンクの `href` が変わったときだけ、その投稿に印を付けます。
  動画の再生時間の表示のような変化や、自分でボタンを付けた変化では印を付けません。
* **次の描画フレームでまとめて処理する。** 印の付いた投稿は `requestAnimationFrame` でまとめて見直すので、
  ボタンは次の描画に間に合います。
* **読む段階と書く段階を分ける。** 要素の大きさを読むとブラウザはレイアウトを計算し直すため、
  読みと書きを交互にすると投稿の数だけ計算が走ります。そこで、すべての投稿を調べ終えてから
  まとめて書き込みます。大きさを読むのは、新しく見つけたメディアの置き場所を探すときだけです。
* **付けたボタンを覚えておく。** ボタンとメディア・投稿の対応は `WeakMap` で持ち、DOM を探し直しません。
  要素が消えれば対応も自動で消えるので、メモリも溜まりません。
* **クリックは 1 か所で受け取る。** ボタンごとにリスナーを付けず、document のキャプチャフェーズで
  まとめて受け取ります。ページ側のどの要素よりも先に受け取れるので、SNS 側の処理（投稿を開くなど）が
  動く前に止められます。

差し込みは冪等で、すでにボタンのある投稿にはボタンを増やさず、保存済みかどうかの見た目だけを整え直します。
見た目が前回と同じなら DOM に触りません。1 件の投稿で例外が起きても、残りの投稿の処理は続けます。

個別ボタンには、「大きさを持っていて、かつ同じ投稿の他のメディアを含まない」祖先要素が必要です。
そうしないと 4 枚組のボタンが全部同じ角に重なってしまいます。`anchorOf()` がサムネイルから
上へ辿ってその要素を探します。画像の読み込み前などで大きさがまだ無いときは、
0.5 秒おきに 6 回までやり直し、それでも見つからなければその 1 件は諦めます。

### いいねボタンの見張り方

いいねボタンは、実は 1 つではなく 2 つあります。X はいいね済みになると
`data-testid="like"` が `data-testid="unlike"` に入れ替わり、Bluesky も同様に
`likeBtn` と `unlikeBtn` に分かれます。アダプタには前者だけを渡しているため、
「いいねなら保存、取り消しなら何もしない」が、状態を自前で覚えることなく
セレクタだけで決まります。

待ち受けは `document` のキャプチャフェーズに置いてあります。サイト側が途中で
イベントを止めても先に届くためです。ただし読み取るだけで、`preventDefault()` も
`stopPropagation()` も呼びません。いいねはサイト側の仕事のままです。

**あえてやっていないのは、DOM の状態変化を監視する方式です。** その方式なら
キーボードショートカットも拾えますが、両サイトともスクロール中に要素を使い回すため、
使い回された要素の状態変化と本物のいいねが区別できません。勝手に始まるダウンロードは、
たまに始まらないダウンロードより害が大きい。そう考えて、確実なクリックだけを対象にしました。

### 保存と、失敗したときの動き

バックグラウンドは、しばらく暇だとブラウザに止められます。Chrome は 30 秒間なにも起きないときと、
1 つのイベントの処理が 5 分を超えたときに止めます。Firefox は 30 秒間イベントが届かないと止め、
API を呼んでいるだけでは延長されません。そのため「保存が終わるまで関数の中で待ち続ける」作りにはせず、
**いつ止められても続きから動ける**ようにしています。

* **保存待ちの列・保存中の 1 件・カウンターを、変わるたびに `storage.session` へ書き出します。**
  止められて起こし直されたときは、そこから読み戻して続きを処理します。
* **保存の依頼には、受け付けた件数だけをすぐに返します。** 結果は後から、
  カウンターと保存できた 1 件（`smdUpdate`）・ボタン 1 回分の結果（`smdBatch`）で知らせます。
  ボタンの「保存中」表示は `smdBatch` が届いたときに解けます。
* **完了は `downloads.onChanged` イベントで受け取ります。** `downloads.download()` は転送が
  **始まった**時点で返ってくるので、完了か 404 かはこのイベントで分かります。
  成功として数えるのは `complete` になったときだけです。
* **30 秒ごとに `alarms` で見回ります**（保存待ちがあるときだけ）。イベントの取りこぼしを拾い、
  受信量が **3 分間**増えなかったダウンロードは止まったものとみなして打ち切ります。
  合計時間では判断しないので、遅い回線での大きな動画も最後まで待てます。
  打ち切ったダウンロードは、ユーザーが一時停止しただけかもしれないので消さずに残します。

保存は投稿をまたいでも**1 件ずつ順番に**行います。同時に保存すると失敗しやすく、
「常に保存ダイアログを表示する」がオンのときにダイアログが一度に何枚も開いてしまうためです。
保存先の URL とファイル名はバックグラウンド側でも検証し、X のメディア配信ホストか Bluesky の
`getBlob` 以外の URL や、ダウンロードフォルダの外を指すファイル名は保存しません。
弾いたものは失敗として数えます。

失敗したものは再試行します。回数は 3 回、待ち時間は 0.3 秒 → 0.8 秒 → 1.5 秒です。
やり直しても結果が変わらない中断理由（404、403、空き容量不足など）は
再試行を飛ばしてその場で失敗にします。失敗した試行は次を始める前に履歴から消すため、
最後まで届かなかったファイルは何も残しません。壊れたファイルも、失敗の記録もです。

保存ダイアログを閉じた場合や、ダウンロード一覧からキャンセルした場合は、失敗には数えません
（カウンターの「DL失敗」にも入らず、トーストも出ません）。

### カウンターと保存済みの記録

カウンターは保存待ちの列と一緒に `storage.session` に置き、ファイル 1 件の状態が変わるたびに、
開いている X / Bluesky のタブすべてへ `smdUpdate` メッセージで知らせます
（保存できた 1 件があれば、それも同じメッセージに載せて、知らせる回数を半分にしています）。
列と一緒に保存しているので、バックグラウンドが止められても数は正しいまま残ります。
「いつ消すか」の時刻（`hideAt`）もバックグラウンドが決めて一緒に送るため、
どのタブでもカウンターが同じ瞬間に消えます。消えた後に次の保存が始まると、数を 0 から数え直します。

保存済みの記録は `storage.session` に置きます。形式は `{ "x:1234567890": 値 }` で、
キーは「サイト:投稿 ID」、値は「メディア総数 × 2^32 ＋ 保存済みの番号のビット」という 1 個の数値です。
ビットは「n 番目（0 始まり）を保存済みなら、下から n ビット目が 1」という数で、たとえば 4 枚中
1 枚目と 3 枚目を保存済みなら `4 × 2^32 + 0b101` です。投稿ごとにオブジェクトや配列を持つより、
メモリも、タブとのやり取りも、書き出しも軽く済みます（そのため 1 投稿のメディアは 32 件までを記録の対象にします。
X も Bluesky も実際は 4 件まで）。上限は 3000 投稿で、古いものから捨てます。
タブ側は開いた時点で `smdState` を送って、それまでの記録とカウンターの値を受け取ります。

X は投稿の要素を別の投稿の表示へ使い回すことがあります。リンクの `href` の変化も見張っているので、
表示中の投稿が変わればボタンを描き直します。保存済みの知らせが届いたときは、その投稿を表示している
ところだけを描き直します。

拡張機能は通常ウィンドウとシークレットウィンドウで同じバックグラウンドを共有するので、
カウンターも記録も送り主のタブの `incognito` で分けて持ちます。`storage.session` は
ブラウザ全体を閉じるまで残るため、シークレット側の記録は `windows.onRemoved` で
最後のシークレットウィンドウが閉じたことを検知して消しています。

## ❓ 困ったときは

**投稿にボタンが出ない**
その投稿に、対象として認識できるメディアが無い状態です。リンクカードのプレビュー、Tenor の GIF、
引用先のメディアは意図的に除外しています。タイムラインの描画途中だった場合は、
スクロールで一度画面外に出して戻すと再走査されます。ライトボックス（拡大表示）にはボタンを出しません。

**いいねを押しても保存されない**
まず設定がオンになっているか確認してください（既定はオフです）。次に、その投稿に対象として
認識できるメディアがあるかを確認してください。引用先のメディア、リンクカードのプレビュー、
Tenor の GIF は、ボタンの場合とまったく同じ理由で除外されます。
なお X のキーボードショートカット `L` によるいいねは検出できません。いいねボタンの
クリックだけが対象です。また、保存済みのメディアはいいねでは保存し直しません
（ボタンがチェックマークになっていれば保存済みです）。もう一度保存したい場合は、
ダウンロードボタンを押してください。ボタンからなら何度でも保存できます。

**保存済みの表示が消えた**
記録はブラウザを閉じると消えます。拡張機能を更新・再読み込みしたときも同様です。
シークレットウィンドウの記録は、シークレットウィンドウをすべて閉じた時点で消えます。

**カウンターの数が、このタブで押した数より多い**
カウンターは開いているすべてのタブの合計です（シークレットウィンドウの分は別に数えます）。
別のタブで保存しているものも含まれます。

**X で「メディアURLを取得できません。ページを再読み込みしてください」と出る**
その投稿の GraphQL レスポンスを横取りできておらず、DOM からのフォールバックでも拾えなかった状態です。
`src` が blob の動画では通常こうなります。ページを再読み込みすれば、横取りが有効な状態で
X が取得し直すので解決します。

**Bluesky で、特定のアカウントだけ失敗する**
そのアカウントが `did:web` で自前サーバーを運用している可能性が高いです。DID ドキュメントは
そのアカウントのドメイン上にあり、`host_permissions` の範囲外なので PDS を解決できず、
`bsky.social` にフォールバックします（そこには実体がありません）。
`manifest.json` の `host_permissions` に `"https://*/*"` を足せば解決しますが、
全サイトの読み取り権限を与えることになります。既定をあえて狭くしているのはそのためです。

**「$1件のダウンロードに失敗しました」と出る**
初回と再試行 3 回、計 4 回試して完了しなかった状態です。Bluesky では PDS の解決が
別のサーバーを指してしまっている場合（上の `did:web` の項目を参照）、X ではメディア URL が
期限切れになっている場合がほとんどで、後者はページを再読み込みすれば取り直せます。
失敗した試行は消えているので、書きかけのファイルを掃除する必要はありません。

**拡張子なしで保存される**
テンプレートに `{ext}` がありません。入力欄の下に警告が出ているはずです。

**Firefox で「毎回確認する」が選べない**
Firefox のダウンロード API が対応していないためです。毎回保存先を選びたい場合は、
「常に保存ダイアログを表示する」をオンにしてください。

**ファイル名の一部が消える**
条件ブロックの中の変数が空だったためブロックごと削除されたか、ファイル名に使えない文字が
除去されたか、150 バイトの上限で切り詰められたかのいずれかです。`{text}` は URL を除去するため、
本文が URL だけの投稿では空になります。

**全部同じフォルダに入る／変な階層ができる**
テンプレート中の `/` がサブフォルダの区切りです。不要なら消し、必要なら足してください。

**毎回保存ダイアログが出る／逆に出したいのに出ない**
**「常に保存ダイアログを表示する」** と、ブラウザ本体の「ダウンロード前に各ファイルの保存場所を確認する」の
両方を確認してください。無言で保存するには両方オフにする必要があります。

**別の端末で設定が違う**
設定は `storage.sync` に入るため、ブラウザのアカウントに追従します。
2 台で食い違った場合は、最後に書き込んだ側が残ります。

## 🌐 対応環境

* **Manifest Version:** V3
* **Google Chrome:** 最新版（マニフェスト上の下限は v126）
* **Mozilla Firefox:** 最新版（マニフェスト上の下限は v140.0）

**最新の Chrome と Firefox だけを対象にしています。** 古いバージョンや、その他のブラウザ
（Chromium 系を含む）向けの互換処理は入れていません。

マニフェストに書いてある下限は、実際に使っている機能から決まっています。Chrome 側は、
URL の検証に使っている `URL.parse`（Chrome 126）です。これより古い Chrome にはインストールできません。

Firefox 側の下限だけは、JavaScript や CSS の機能ではありません。「この拡張機能は何も収集しない」と
宣言している `browser_specific_settings.gecko.data_collection_permissions` が理由です。
Firefox がこのキーを解釈できるのは **140 以降**で、Mozilla 自身も、宣言が黙って無視される環境に
インストールされないよう `strict_min_version` を合わせることを推奨しています。

マニフェストは Chrome 用（`manifest.json` と、その原本の `manifest-chrome.json`）と
Firefox 用（`manifest-firefox.json`）に分かれています。違いは、バックグラウンドの宣言
（Chrome はサービスワーカー、Firefox はイベントページ）と、ブラウザごとの設定キー
（`minimum_chrome_version` と `browser_specific_settings`）の 3 つだけです。

**Android 版 Firefox には対応していません。** この拡張機能の根幹である `downloads` API の
サポート状況がドキュメント上でも一貫しておらず、`saveAs: true` はエラーになることが
知られています。実機で検証しないまま「対応」と書くのは推測になるため、載せていません。

## 🔒 プライバシー

解析・テレメトリ・識別子・広告・開発者のサーバー、いずれもありません。

要求する権限は `downloads`（ファイルの保存と、その 1 件が完了したかの追跡。失敗時の
再試行と後片付けに使います）、`storage`（4 つの設定と、ブラウザを閉じるまでの保存済みの記録・
保存待ちの列）、`alarms`（保存中のダウンロードを 30 秒ごとに見回る）の 3 つ、
それに `x.com` / `twitter.com` / `bsky.app` / `public.api.bsky.app` / `plc.directory` へのアクセスです。

外部通信は行いますが、その範囲ははっきりしています。**保存が始まったときだけ**
（ダウンロードボタン、または有効にしている場合はいいね）、Bluesky の公開 API と
投稿者の PDS に対してのみです。X に対しては、この拡張機能からの通信は
一切ありません。ページが既に受け取った応答を読んでいるだけです。
どのメディアを保存したかは、保存済みの表示のために端末内の `storage.session` にだけ記録され、
同期も送信もされず、ブラウザを閉じると消えます。何を見たか、どの投稿にいいねしたかは記録しません
（いいねで保存した場合も、残るのは「保存した」という事実だけです）。
詳しくは [PRIVACY.md](PRIVACY.md) を見てください。

## 🧑💻 開発者向け

### ファイル構成

```
manifest.json             拡張機能マニフェスト（MV3）— manifest-chrome.json と完全に同一
manifest-chrome.json      Chrome 用: minimum_chrome_version・サービスワーカー
manifest-firefox.json     Firefox 用: browser_specific_settings・イベントページ
background.js             サービスワーカー: 保存の順番待ち（再試行つき・止められても再開）/ カウンター / 保存済みの記録 / Bluesky API / DID→PDS 解決 / キャッシュ
popup.html/.css/.js       設定画面（オプションページも兼用）
content.css               ボタン・トースト・カウンターのスタイル（両サイトへ注入）
shared/template.js        SMD     — i18n・ファイル名テンプレート・既定値
shared/core.js            SMDCore — ボタン注入・保存フロー・トースト・カウンター・保存済みの表示
sites/x/interceptor.js    MAIN world: fetch / XHR を包んでメディア URL を集める
sites/x/content.js        X アダプタ
sites/bluesky/content.js  Bluesky アダプタ
_locales/                 9 言語分の UI 翻訳
icons/
```

`shared/core.js` がサイトに依存しない処理をすべて持ちます。各サイトはアダプタを 1 つ作って
`SMDCore.start()` に渡すだけです（必須 6 キー ＋ 任意 1 キー）。

| キー | 役割 |
| :--- | :--- |
| `site` | `"x"` / `"bluesky"`。`<html data-smd-site>` 経由で CSS のアクセント色を切り替える |
| `postRoot` | 投稿 1 件のコンテナを選ぶセレクタ |
| `mediaContainers(root)` | メディアを包む要素の配列 |
| `postId(root)` | 投稿 ID だけを素早く返す（または `null`）。ボタンを描き直すたびに呼ばれるので、軽く作ります |
| `readPost(root)` | `{ site, screenName, postId, name, text, time }` または `null`。本文なども読むので重くてよく、保存するときだけ呼ばれます |
| `getMedia(root, post)` | `[{ kind, url, ext, id, res }]` を `mediaContainers` と同じ並びで返す。URL が分からないものは取り除かずに `null` にする（個別ボタンは位置で対応するため）。`post` に情報を補ってよい |
| `actionBar(root)` | メインボタンを置く要素 |
| `likeButton` | **任意**。いいね連動保存で使う、いいねボタンのセレクタ。「いいねを取り消す」ボタンには**一致してはいけません**。省略するとこの機能だけが無効になります |
| `watch` | **任意**。ボタンに関係する要素（メディア・投稿へのリンク・操作バーのボタン）のセレクタ。投稿の中でこれに当てはまる要素が増減したときだけボタンを見直します。省略すると投稿の中のどんな変化でも見直します（動きますが重くなります） |

### サイトを追加するには

上記のキーを持つアダプタを書き、`manifest.json` にコンテンツスクリプトの項目
（必要なら `host_permissions` も）を追加し、`{site}` が意味のある文字列になるよう
`shared/template.js` の `SITE` 表に追記し、`content.css` にアクセント色のブロックを足します。
`shared/core.js` は触らずに済むはずです。

### デバッグ

ビルド工程が無いので、`chrome://extensions` の **更新（リロード）** だけで編集内容が反映されます。

* **コンテンツスクリプト、トースト、カウンター** — ページ側のコンソール。
* **interceptor** — 同じくページ側のコンソール。ただし MAIN world で動くため、
  X 本体とグローバル変数を共有している点に注意してください。
* **`background.js`** — 拡張機能ページから開けるサービスワーカーのコンソール。
  アイドル状態になると停止し、次のメッセージで再起動します。そのときキャッシュは空になりますが、
  再取得できるので問題ありません。保存待ちの列・カウンター（キー `queue`）と保存済みの記録は
  `chrome.storage.session.get()` で中身を確認できます（こちらはサービスワーカーが止まっても消えません）。

なお `popup.js` は `chrome.i18n.getUILanguage()` を見て表示言語を決めます。
特定の言語の表示を確認したい場合は、ブラウザの表示言語を切り替えるか、
テスト用に `default_locale` を変えて読み込んでください。
